# 异步任务管理优化方案

## 当前问题与边缘情况

### 1. 任务状态管理中的竞态条件
- 任务状态转换（执行中 → 已完成）不是原子操作，在多个异步操作与同一任务交互时可能导致状态不一致
- 在 `RuleTask.execute_tool()` 中，任务在 `finally` 块中被标记为完成，但如果调度器在执行过程中尝试检查任务状态，可能存在竞态条件

### 2. 错误处理与恢复
- 虽然针对网络和超时错误有重试逻辑，但 `_handle_tool_result` 方法中的失败没有恢复机制
- `get_output_stream()` 中的错误处理较为简单，没有明确的策略来处理死锁或卡住的任务

### 3. 资源管理
- 长时间运行的任务没有明确的超时机制，可能导致资源耗尽
- 如果任务没有正确清理，`_active_task_executions` 集合可能无限增长

### 4. 并发控制
- 没有限制可以同时运行的任务数量，可能导致资源耗尽
- 没有任务优先级机制，这对关键操作可能很重要

### 5. 死锁潜在风险
- 在 `get_output_stream()` 中，"没有更多可运行任务"的检测可能不准确，特别是当任务在等待一个永远不会发生的事件时
- 如果任务不断被添加但从不完成，`get_output_stream()` 中的循环可能永远不会终止

- 可以增强当前的事件驱动架构，使其更具弹性

```python
# 带事件缓冲的增强型 EventBus
class EnhancedEventBus(EventBus):
    def __init__(self, buffer_size=100):
        super().__init__()
        self._event_buffer = collections.deque(maxlen=buffer_size)
        
    async def publish(self, event_type: str, **kwargs: Any) -> None:
        # 缓冲事件
        self._event_buffer.append((event_type, kwargs))
        
        # 常规发布
        await super().publish(event_type, **kwargs)
        
    async def replay_events(self, event_type: str = None) -> None:
        """重放缓冲的事件，可选按类型过滤"""
        for buffered_type, kwargs in self._event_buffer:
            if event_type is None or buffered_type == event_type:
                await super().publish(buffered_type, **kwargs)
```

- 添加资源使用跟踪和限制
- 在系统负载过重时实现优雅降级
